# NEURO — Nick's Executive Utility & Reasoning Orchestrator

Personal AI-powered productivity system. Aggregates Jira queue, Obsidian vault, Microsoft 365 (calendar/tasks/email), Strava, location tracking, and AI chat into a single PWA. Runs on Raspberry Pi 5 (16GB) via Tailscale, installed as PWA on iPhone.

## NEURO vs SARA — the division of labour (Nick, 15 Aug 2026)
**NEURO is the brain**, and the NEURO app is Nick's *direct* access to it when he goes looking. **SARA is the J.A.R.V.I.S. layer**: she uses NEURO's brain and **comes to him** — prompts, pushes, helps — and is the visual/audio route for interacting with the brain conversationally rather than by navigating a UI. Neither replaces the other, and **nothing in `sara/` is scaffolding to retire.** Practical consequences: `sara/app` (phone PWA) already talks DIRECTLY to the NEURO backend and never touches `sara/backend` — it is a NEURO client, so there is nothing to "fold in". `sara/backend` (:3005) exists to serve the **Pi 4 desk kiosk** (`sara/frontend`), which is the *ambient* half of SARA. Judge any SARA change by whether it helps her come to Nick; judge any NEURO change by whether it makes the brain better or the direct access clearer.

## Tech Stack
- **Backend:** Express 4 + Node.js (CommonJS, `require()` — NOT ESM)
- **Frontend:** React 19 + CSS modules (per-component `.css` files) + Vite
- **Database:** better-sqlite3 (native SQLite, WAL). Writes commit immediately — no flush step, and external scripts can read while the server runs.
- **Auth:** PIN-based (`X-NEURO-PIN` header) + API token for machine clients (n8n)
- **AI:** Anthropic SDK (Claude) + Ollama (local models on Pi) with AI routing layer
- **External:** Jira REST, Microsoft Graph (MSAL device code), Strava OAuth, OwnTracks, Obsidian vault filesystem, n8n webhooks, web-push notifications
- **Monorepo:** npm workspaces — `backend/`, `frontend/`, `worker/`
- **Worker:** RETIRED 2026-08-15 (`PI4_WORKER_ENABLED=false`). The Pi 4 managed 12 tokens/sec prompt processing on the SMALLEST model available, so a ~3,700-token triage payload needed five minutes just to read the prompt. Not a model-sizing problem — a hardware ceiling. Code and config are left in place so re-enabling is one env var. Background tasks now route: heavy prose work (email_triage, transcript_processing) to cloud, light work (import_classification, journal_prompts) to Pi 5 Ollama.

## Architecture

### Backend (`backend/`)
- `server.js` — Express bootstrap, PIN auth middleware, route wiring, SPA fallback (262 lines)
- `db/database.js` — sql.js init, state KV store, query helpers
- `db/schema.sql` — Full schema (conversations, jira cache, todos, calendar, inbox, vault embeddings, entities, do-next, location visits, task MoSCoW, nudges, SARA actions, daily summary)
- `routes/*.js` — ~40 Express route modules (CommonJS `module.exports`), incl. `vault-hygiene` (lint / contextual-link / alias-suggest)
- `services/*.js` — ~45 business logic modules including AI pipelines, vault access, Jira sync, Microsoft Graph, scheduling, and `vault-hygiene` (deterministic vault-graph maintenance)

### Frontend (`frontend/src/`)
- `App.jsx` — Main SPA shell, tab navigation
- `components/*.jsx` — ~35 view components, each with matching `.css` file
- `api.js` — API client with PIN header injection
- `cacheStore.js` + `useCachedFetch.js` — IndexedDB offline caching (idb library)
- `usePushNotifications.js` — Web push subscription management
- `voiceUtils.js` — Voice input utilities

### SARA mobile (`sara/app/`)
- The PWA on Nick's phone. Seven tabs: Focus, Tasks, Capture, Voice, Chat, Prep, Brain.
- `views/Tasks.jsx` is the browsable task list — before it, capture was one-way on mobile and the only way to tick something off was to arrive via a notification. Reads `/api/todos/focus` so its ranking matches Focus and the rest of NEURO.
- `completeTask.js` is the ONE place that knows how to close a task, shared with `NotificationActionCard`. Owner order is `task_id` → `ms_id` → `filePath`+`lineNumber`; getting it wrong is silent (a null `filePath` just 400s and the task stays open).
- Tab ids must also exist in `SARA_LITE_TABS` in `shared/action-surfaces.cjs`, or notification routing falls back to Focus.
- **Voice loop (15 Aug 2026, #90)** — `sara/app/src/voiceUtils.js` started as a verbatim copy of `frontend/src/voiceUtils.js` and has since **diverged, deliberately**: the shared version was only ever proven on desktop, and three things it does are wrong on iOS. (1) The gesture unlock spoke an EMPTY utterance — iOS drops a zero-length one without queueing it, so the unlock silently no-ops and every later `speak()` is ignored; it now speaks a single space at volume 0, and `unlockAudio` is exported so the 🔊 tap can unlock explicitly rather than relying on whichever touch wins the `{once:true}` race. (2) `cancel()` ran unconditionally before every `speak()`, a known way to wedge iOS; it is now guarded on `speaking||pending` and followed by `resume()`. (3) `speakSara` returns the utterance so callers can watch `onstart`/`onerror`. **Port these back to `frontend/` before touching either copy** — they are harmless on desktop and the two files are meant to track each other. `pickVoice()` falls through an en-GB ladder, logging the full voice list when nothing matches. `views/Chat.jsx` owns both halves: a persisted 🔊/🔇 toggle (`sara_voice_out`, OFF by default — a PWA that talks unprompted on a train gets disabled forever) and a 🎤 composer button. **Speech-out is gated on `busy`, never on `messages`** — keying that effect on `messages` speaks every streamed token. Dictation is `continuous`, so the stop tap is what sends (also the iOS audio-unlock gesture); `onend` fires from a stale closure, hence `dictatedRef`/`busyRef` rather than state. Note the `voice` tab mounts **Capture** with `autoRecord`, not Chat — the talk→hear loop lives on the Chat tab. Chat only: briefings and nudges (NEURO's `speakIfEnabled`) are not spoken on the phone yet, and there is no wake word (#11 parked).

### Worker (`worker/`)
- Separate Express app on port 3002 for Pi 4
- Ollama-powered AI tasks only — email triage, import classification, journal prompts, transcript processing
- Auth via `WORKER_SECRET` header
- Stateless: processes tasks, returns results, owns no data

### MCP Server (`mcp-server/`)
- Standalone MCP server exposing NEURO APIs as tools for external Claude Code sessions
- Vault tools are **NEURO-first with local-vault fallback**: they call `/api/vault/*` (writes re-index embeddings/entities via vault-hooks); on transport failure (Pi down) they fall back to direct filesystem access via `OBSIDIAN_VAULT_PATH`, served by the `localVault` helper + `vaultDispatch` circuit breaker. NEURO reconciles offline writes on next startup (hash-based `rebuildEmbeddings`). `delete_note` is NEURO-only (needs index cleanup); `vault_backlinks`/`related_notes` degrade gracefully offline.
- Env: `NEURO_URL`, `NEURO_PIN`, `NEURO_VAULT_KEY` (→ `X-Api-Key` for `/api/vault`), `OBSIDIAN_VAULT_PATH` (local Syncthing copy for fallback)

## Key Patterns
- **CommonJS throughout backend** — `require()` / `module.exports`. NOT ESM. No `import` statements.
- **PIN auth middleware** — all `/api/*` routes require `X-NEURO-PIN` header or `?pin=` query param. Machine clients use `X-NEURO-API-TOKEN` instead.
- **State KV store** — `db.getState(key)` / `db.setState(key, value)` for runtime state (sync status, last errors, etc.)
- **AI routing (policy rewritten 14 Aug 2026)** — `ai-routing.js` routes by **latency need, not by vendor ladder**. `LATENCY_SENSITIVE_TASKS` (chat, standup/EOD interactive + questions, email draft/summary, briefing synthesis) → **OpenRouter first**, because the Pi's local models are too slow to hold a conversation with. Everything else — light, scheduled, background — → **Ollama first**, cloud only if local fails. `_providerOrder(taskType)` is the single source of that decision and both `runTask` and `runStreamingChat` iterate it. **Anthropic and OpenAI are backstops, never the default**: they were tiers 1 and 2 until the Anthropic key ran out of credit and, being first in line, took chat and the standup down with it. Pinned by `ai-routing.test.js` — if you change the order, those tests should fail. Tool calling: `getToolProvider(taskType)` picks the provider for a tools turn (OpenRouter preferred, Anthropic fallback, null if neither) — both providers expose an identical `chatWithTools(systemPrompt, messages, tools, runTool, options)` returning `{text, usage, toolCalls}`, so callers stay provider-agnostic. Ollama has no function-calling API, so no cloud provider = no tools, and chat/standup degrade to plain conversation rather than pretending.
- **One vault exclude list (15 Aug 2026, #85/#34/#86)** — `services/vault-exclusions.js` is the single source of what is not content. It separates **generated** (`Vault Audit`, `SARA Import Reports`, and by FILENAME the task export / `Master Todo` / MoSCoW worksheets / `.backup-` / `.sync-conflict-`) from **retired** (`Archive`, `_toDelete`), because a linter resolving link *targets* still needs to see the retired half — that distinction is the fix for #81, not an oversight. `Daily/` is excluded from embeddings and **kept** for entity extraction: "who did I mention on Tuesday" is exactly what a daily note answers, and exactly what a semantic index of hundreds of scratchpads ruins. Used by `embeddings.js` and `entities.js`; the other copies (`obsidian.js`, `people-gap.js`, `plaud-sync.js`, `one-to-one-detect.js`) are deliberately untouched for now — each is scoped to its own job. **Skipping on the walk only stops NEW rows**, so both consumers prune: `rebuildEmbeddings` drops rows no longer indexable, `entities.pruneExcludedEntities()` runs at the head of the nightly sweep.
- **Embeddings are multi-chunk (15 Aug 2026, #79)** — `prepareFile` returns EVERY chunk; it used to compute them all and return `chunks[0]`, so the DB held 3,216 rows all at `chunk_index 0` and everything decided in the back half of a meeting was unreachable by search, chat RAG and the MCP tools. Invisible, because search always returns something. Bounded at `MAX_CHUNKS_PER_FILE = 60`, logged when hit — **sized against the live vault, not guessed**: 1,091 indexable notes, median 4 chunks, p90 20, p99 60, max 151. The first cut used 20 and would have truncated 107 files, i.e. the top 10% and precisely the long transcripts this fix exists for. The bound is for cost on outliers only; result dominance is handled by the best-chunk-per-file fold, not by this number. A full re-index is **~8,400 chunks** against 3,215 before. Three invariants: the unchanged-check compares content hash **AND** `getEmbeddingChunkCount` (or files indexed under the old code look done forever); rows are **deleted before re-save** (a shortened note has fewer chunks and `INSERT OR REPLACE` alone orphans the tail); and `semanticSearch` folds to the **best chunk per file** before slicing, or `maxResults` counts chunks and one transcript fills the results with itself. `isConfigured()` reads `VOYAGE_API_KEY` — it read `ANTHROPIC_API_KEY`, a different vendor, and only worked because both are set on the Pi. Pinned by `embeddings.test.js`. **The index does not improve until a rebuild runs.**
- **Graph collections are paged (15 Aug 2026, #29)** — `graphFetchAll()` follows `@odata.nextLink`; `$top` is a page size, never the answer. Used by `calendarView`, To Do tasks and Planner. Two traps: `graphFetch` returns `null` on 401 and callers read that as "use the NOVA bridge", so the helper returns `null` rather than an empty collection — an empty one reads as *"you have no meetings"* and the fallback never fires. And a page cap or a mid-collection failure sets `truncated: true` **and logs**, because a silent cap is the bug (third instance of that species in two days: calendar `$top=50`, the 1,958-key JQL, Planner `$top=200`).
- **Action candidates gate on content, not mtime (15 Aug 2026, #78)** — `syncNoteActionCandidates` hashes the body **after stripping frontmatter** and short-circuits when it is unchanged, so a bulk `people:` restamp is invisible by construction. That flood was real: 229 notes restamped on 14 Aug moved every mtime into `scanRecentNotes`'s 7-day window and 911 candidates landed in one night — one automation's bulk rewrite triggering another's. `scanRecentNotes` also takes `maxCreate` (default 60) and **logs loudly** when it caps: a run proposing hundreds has failed regardless of whether each item is defensible. Pinned by `action-candidates-hash.test.js`.
- **The AI budget survives a restart (15 Aug 2026, #55)** — `_usage` in `ai-routing.js` persists to `agent_state.ai_routing_usage` on every recorded call. A module-level counter made the daily cap really mean *per uptime*, and the backend restarts several times a day. Yesterday's stored blob is discarded, not carried.
- **Vault sync** — Syncthing over Tailscale (replaced Git-based sync). Obsidian vault at `C:\Users\NickW\Documents\Nicks knowledge base`
- **Plaud intake** — `plaud-sync.js` writes transcript + preferred Plaud summary/Obsidian note, then `imports.js` routes the note of record into canonical vault paths: meetings in `Meetings/YYYY/MM/` and transcripts in `Meetings/transcripts/YYYY/MM/`, while enriching people links and keeping backlinks aligned
- **Plaud cleanup** — `/api/plaud/cleanup` and `imports.backfillPlaudNotes()` backfill historical Plaud notes, re-route legacy meeting-note copies into correct folders, archive duplicate variants, and write a cleanup report into `Documents/System/SARA Import Reports/`
- **Vault hygiene** — `services/vault-hygiene.js` is the deterministic graph-maintenance engine (pure CommonJS, takes vault root so it runs in-process or standalone via `node`). Capabilities: `lint`, `contextualLinkPlan`/`Apply`, `aliasSuggest`, `fixPlan`/`fixApply` (tiered: skip|conservative|moderate|aggressive — links default conservative=exact-only; fuzzy mislinks here so it's review-only), `connectOrphans` (fallback), `graphConfig`. Read-only by default; mutating ops are append-only/surgical, back up every touched file to `Scripts/.lint-backups/<ts>/`, write a changelog, and are idempotent (markers `<!-- ctx-links -->`, `<!-- hub-link -->`, `<!-- daily-nav -->`). Precision rules: FULL-NAME matching only, strip wikilinks/code/paths before matching, resolve path-form links when deduping, skip names mapping to >1 person. Reports → `Documents/System/Vault Audit/`. Exclude set must include generated output (`Vault Audit`, `.lint-backups`, `Archive`…) or scans self-pollute. Wired into the scheduler as a READ-ONLY Friday 4:35pm pass (refreshes lint + link cards, never applies). Ports of the throwaway `Scripts/_*.js` prototypes; full spec in `Projects/NEURO/Vault Hygiene Engine — Build Handoff` (vault).
- **PLAUD reconcile/repull** — `plaud-sync.js` `reconcilePlaudRecordings()` (read-only) lists every PLAUD recording and finds those with no ACTIVE note (Archive excluded) by plaud_id or date+title-token Jaccard ≥0.5; `repullPlaudRecordings({ids?,limit?})` re-pulls them FRESH (never from Archive) through the existing throttled (750ms gap, concurrency 1), 429-backoff-with-jitter, ledger-persisted-per-recording pipeline — resumable: a crash continues from the ledger. The §9.3 "no throttling" lesson was about the separate Obsidian plaud-mcp-sync plugin, NOT this service.
- **Pi health** — `services/pi-health.js` reads live host state (load, SoC temp, `vcgencmd get_throttled` decoded to named flags, `/proc/meminfo` MemAvailable, `df`, SMART via `sudo -n smartctl -d sat`, `pm2 jlist`, `systemctl is-active`, `ps`). Pure read-only, no DB. Every section degrades to `null` off-Linux or when a tool is missing, so it doesn't break Windows dev. SMART cached 5min (spins the disk), PM2 15s; a 60s in-memory ring buffer (120 samples, `.unref()`) feeds the trend sparklines. `assess()` turns raw numbers into the ranked issue list the panel's focus band renders — that judgement lives in the backend, not the component.
- **Tasks: NEURO is the source of truth** (13 Aug 2026) — the `tasks` table owns text, status, MoSCoW, priority 1-3, due date and a provenance backlink. `task_moscow` is folded in and no longer written. All four capture routes write to the DB: `/api/capture/todo` (Watch/Siri + Capture tab), chat, MCP `create_task`, and SARA suggestion approval — `obsidian.addTodoToMasterList()` is now a thin wrapper that creates a task rather than appending markdown, which retired both the `📥 Inbox` heading guessing and `#mustdo`. `services/task-store.js` is the only writer (dedupe_key = normalised text, UNIQUE, so a second sighting folds rather than duplicates); `task-export.js` regenerates `Tasks/NEURO Tasks (export).md` (read-only copy + "last exported" stamp = the offline safety net and the rollback path; `verifyExport()` compares it to the DB by task id); `task-import.js` seeded 130 tasks from `Master Todo.md` with MoSCoW/priority from the 12 Aug triage worksheets. `parseVaultTodos()` merges DB rows and dedupes file-backed lines against them, so every consumer sees tasks unchanged. Microsoft Tasks and daily notes stay file-backed — Microsoft and the daily note own that data. `Master Todo.md` is still parsed as a fallback until `agent_state` key `tasks.master_todo_retired` is set (`POST /api/tasks/retire-master`, refuses unless the export verifies).
- **Feature capture (15 Aug 2026)** — `services/feature-tracker.js` appends to `Projects/NEURO/NEURO Feature Tracker.md` in the vault, the file the whole NEURO/SARA/NOVA backlog lives in. Two front doors: the `capture_feature` chat tool (tier **write** — internal and reversible, so it runs immediately) and `POST /api/capture/feature`, which is what SARA Capture's **Feature** mode and NEURO CapturePanel's `feature:`/`idea:`/`neuro:`/`sara:`/`nova:` prefix both call. **Deliberately not a task** — a feature idea filed as a todo is one nobody reads next to the other 92, and the tracker is where ranking happens. The writer is append-only and surgical like vault-hygiene: one row into a `## Captured — raised in passing` section (created above `## Related` on first use), plus the `updated:` stamp. It **never renumbers or reorders** — the ranked sections are Nick's editorial. Numbering is `max(existing)+1`, **not a count**, because the file already contains a duplicate #103 and a count would silently mint a third. Pinned by `feature-tracker.test.js`. The web panel only routes on an **explicit prefix**: everything else there is guessed from prose, and guessing "that's a feature" would file thinking as backlog.
- **Route 3 — the Obsidian capture drop-box** — `Tasks/Capture.md` is a DROP-BOX, NOT A STORE. `task-capture-drain.js` creates the tasks and CLEARS the line (scheduler every 10 min + on startup, audit trail in `Tasks/Archive/Capture drain log.md`). If lines lingered it would silently become a second source of truth. Being one-way is why capture keeps working while the Pi is down. Inline hints: `!must` `p3` `@YYYY-MM-DD`. Deliberately NOT named `New ToDos.md` — an old file by that name is in `Tasks/Archive/`.
- **Two-way Microsoft writes** — Graph delegated scopes are `Calendars.ReadWrite, Mail.ReadWrite, Mail.Send, Tasks.ReadWrite, User.Read, Chat.Read, People.Read` (`GRAPH_SCOPES` in `microsoft.js`) — the three widened/added on 14 Aug 2026 (calendar create, mark-read on dismiss, name→email) are all user-consentable, so the device-code flow still completes without admin approval; MSAL persists to `.ms365-token-cache.json` so restarts keep auth. Adding a scope needs a fresh device-code flow (`POST /api/microsoft/auth`) AND tenant admin approval — the consent screen raises the request. `graphFetch` is GET-only; writes go through `graphWrite`. Email replies use `/me/messages/{id}/reply` (threads + quotes) and dismiss from triage on send. Task completion: To Do PATCHes `status`, Planner needs an `If-Match` etag so it reads first — `Tasks.ReadWrite` covers both, `Group.ReadWrite.All` is NOT required. The vault stores only a bare `<!--id:...-->` with no list, so `fetchTodoTasks` caches task→list and a cold start searches the lists. `/api/todos/complete-ms` reports whether the push landed and keeps the Power Automate webhook as fallback; the vault line toggles either way.
- **Standup/EOD as a session (14 Aug 2026)** — `services/standup-session.js` replaces the fixed three-question stepper with a tool-using conversation. State machine `active → ready → finished`, one session per day per kind, persisted in `agent_state` as `standup_session_<kind>_<date>` (KV, not a table — a schema migration on the live DB is a bigger risk than the query convenience is worth). **The transcript is saved before AND after every turn**, which is the whole point: the old flow held everything in browser state until one final POST and lost it all when that POST failed. Tools: `resolve_commitment` (a carry of 3+ days must be decided, and `scheduled` only counts if it creates a dated task), `set_focus` / `set_eod_summary` (mark the session ready), `create_task`, `complete_task`. Context is gathered deterministically up front from `standup-accountability` + working memory + task store — a standup that pauses to search the vault is a standup that gets skipped. `finish()` renders the note; it does NOT scrape a `===DAILY_NOTE_START===` marker out of the model output like `/interactive` did. **The `## Focus Today` / `## Carry-Overs` headings are a contract** — `standup-accountability.parseDailyNote()` reads them back tomorrow to work out what was carried, so changing them silently breaks accountability. Routes: `/api/standup-session/:kind/{start,reply,finish,abandon}` + GET to resume; failures return 503 `retryable:true` WITH the saved session so the client can retry without retyping. Falls back to a tool-less conversation when no tool-capable provider is available (`session.degraded`). The old `GuidedStandup`/`GuidedEod` components in `StandupEditor.jsx` are now unreferenced — left in place deliberately while a second session is active in the repo.
- **Chat tool use (14 Aug 2026)** — `services/chat-tools.js` gives chat hands; before this it was read-only RAG, so "mark that done" / "book an hour for it" were impossible by construction. Three tiers, and the tier IS the safety model: `read` (get_queue, get_tasks, get_calendar, search_vault, read_note, get_urgent_emails) has no side effects; `write` (create_task, complete_task, append_daily_note) is reversible and internal, so it runs immediately; `queued` (draft_email_reply, schedule_focus_block) NEVER executes in chat — it creates a pending `sara_action` and the send/booking happens only on approval. The agentic loop is `anthropic-provider.chatWithTools()` (max 5 rounds, history normalised first because the tool API rejects the malformed histories the text path tolerates). Only Anthropic supports tools, so other providers fall back to the text-only path rather than pretending. Gated by `ai-routing.isCloudAllowed('chat_sync')` so AI_MODE and the daily budgets apply; the loop reports its own usage via `ai-routing.recordUsage()` or tool turns under-count. Kill switch `CHAT_TOOLS_ENABLED=false`. With tools live the `[ADD TODO:]` marker is suppressed in the prompt — otherwise the task is created twice. `read_note` resolves inside the vault root and refuses anything else: a model-supplied path is untrusted input.
- **SARA actuators (14 Aug 2026)** — `suggestion-engine.executeAction` is async and does real work, not just navigation: `reply_email` (Graph send + triage dismiss), `complete_task` (task store + Graph push + vault mirror), `schedule_focus_block` (Graph calendar create). Outbound email is deliberately two-gated — `draft_reply` writes the words and queues a separate `reply_email` action carrying them, so nothing sends until Nick has read the draft and approved again. Knock-ons: `/api/actions/batch` no longer runs inside `db.batchSaves()` (better-sqlite3 transactions are sync-only, and the flush-batching it existed for died with sql.js), and `action-candidates.js` lost its hard-disabled auto-promote branch because that function is sync and would have marked every promotion failed. `suggestion-engine.queueAction()` is the front door for anything that wants SARA to act without acting itself.
- **Approving an action (15 Aug 2026, #97)** — `components/ActionsPanel.jsx` (sidebar **Actions**, primary group + mobile bottom nav) is the approval surface for the whole queue. Before it, nothing in either frontend read `GET /api/actions`: `TodoPanel` handled only the todo suggestions in its own payload and `WaitingOn` only `chase_commitment`, so the SECOND gate on outbound email was reachable only via a push notification's action card. **Every word on a card comes from `action.presentation`**, built by `services/action-presenter.js` on the server, from the same stored payload `executeAction` will read — reconstructing it client-side gives a screen free to drift from what actually sends. Per type it returns the **full body verbatim** (never a summary, for anything outbound), the real recipient, `warnings`, and `blockers` restating `executeAction`'s own `{ok:false}` guards; a non-empty `blockers` **disables approve and says why**, rather than an approve that quietly fails. Only payload-inspectable guards live there — anything needing I/O stays the executor's to report. Outcomes persist on screen after the card has gone, because a failed action is marked `failed` and drops out of pending, so a vanished card is otherwise indistinguishable from success. `action-presenter.test.js` parses the `case` labels out of `executeAction`, so **adding an action type without a presenter fails a test** rather than showing a bare card months later. **`getPendingSaraActions` defaults to limit 10** — `/api/actions` called it bare and reported 10 pending against a real queue of **930** (926 `capture_todo` promotion candidates). - **Notification governor (14 Aug 2026)** — every `webpush.sendToAll()` passes `_governor()`: quiet hours (`PUSH_QUIET_HOURS`, default `22:00-07:00`, `off` disables), 30-min dedupe on type+title+body, hourly cap (`PUSH_HOURLY_CAP`, default 6). `ALWAYS_DELIVER` types (escalation_alert, meeting_alert, system_alert, capture_failed, test) bypass quiet hours and the cap but NOT dedupe — the same escalation arriving via both the nudge path and the alert path is still one escalation. - **Calendar writes (14 Aug 2026)** — `POST /api/calendar/events` creates on `/me/events` via `graphWrite`; needs `Calendars.ReadWrite`. `POST /api/calendar/parse` turns free text ("2pm tomorrow with abdi for 30 mins") into a draft and creates NOTHING — `event-parser.js` is regex-first (instant, works with the Pi offline), and only spends a model call via `aiRouting.runTask('event_parse')` when the rules find no time. - **Calendar timezone** — Graph answers in UTC unless asked otherwise, and the UI slices times straight out of the string, so every BST event read an hour early. `fetchCalendarEvents` now sends `Prefer: outlook.timezone="Europe/London"` (`EVENT_TIMEZONE`, env `NEURO_TIMEZONE`), which fixes the times AND makes Graph read the day window as local. - **The person graph (14 Aug 2026)** — `People/*.md` filenames ARE the roster; every consumer reads the folder, and nothing hardcodes a name list. `entities.js` used to carry a 20-name `TEAM_MEMBERS` array and store the **first** name (`Hope`), while `person-detail` looked mentions up by **full** name against an exact-match query — so every person page's Mentions block was empty by construction. Attendee extraction in `imports.js` matched `### Attendees` only — present in 6 of 229 meeting notes, because PLAUD writes `## Mentioned` — so `people:` frontmatter was empty almost everywhere; `PEOPLE_HEADING_RE` now takes either at `##`/`###`. Unmatched names are recorded **bare**, never as `[[People/{slug}]]`: inventing that link is what produced the dangling `{Name}`/`Speaker 1` links. Backfill for existing notes is `POST /api/imports/restamp-people` (`restampMeetingPeople`, dryRun by default, backs up to `Scripts/.lint-backups/`) — it rewrites ONLY the `people:` block by hand, deliberately NOT via `updateFrontmatter`, whose line-based reserialise silently drops list values.

- **1-2-1s are detected, not declared (14 Aug 2026)** — `services/one-to-one-detect.js` derives `last-1-2-1` from the meeting notes in `Meetings/`, because the hand-maintained frontmatter froze in March 2026 while 1-2-1s carried on happening: the Team board showed people 100+ days overdue who had been seen in July. Two rules carry it. (1) **A prep note is not a 1-2-1** — `type: meeting-prep` notes are NEURO-generated *before* a meeting and carry `meeting-type: "1-1"` like the real thing; Heidi had five, each generated off the same stale date with no meeting behind any of them, so counting them would close the loop on itself. `type` must be `meeting` or `transcript` (an orphaned transcript is often the only surviving evidence — the Plaud reset archived some summaries). (2) **Attribution needs the body to agree** — frontmatter `people:` links are Plaud-generated and often incomplete (the 4 Jun three-hander links only Stephen), so a candidate must also dominate the mentions (`MIN_MENTIONS` 12, `DOMINANCE` 0.6), and a title naming 2+ of the team is a group meeting outright. `syncPeopleNotes({apply})` stamps frontmatter and **only ever moves a date forward**, so a manual entry for a meeting not yet written up survives. - **1-2-1 booking (14 Aug 2026)** — `services/one-to-one-booking.js`, "Book now" on the Team card. Two-step like `event-parser`: `propose()` reads the calendar and returns a draft, `book()` creates it — attendees mean Graph emails a real invite, so nothing is created by looking. **Nick's booking rules are expressed as two windows rather than a pile of exclusions** — `AM_WINDOW` 10:00–12:00 and `PM_WINDOW` 14:00–16:30 (bounds in minutes so 16:30 is expressible). That makes "never at 9am", "never 12–2" (the gap between them IS lunch) and "never after 4.30pm" (a slot must *finish* inside its window, so a 30-min 1-2-1 starts no later than 16:00) true by construction. Plus "never when a meeting already exists" (clash detection; tentative blocks, only free/cancelled don't) and `MAX_PER_DAY = 2` via `countOneToOnes()`, which matches existing 1-2-1s by subject however they were named. PM is tried first — every entry in the vault's 1-2-1 Tracker reads "PM". Working days only, from `next-1-2-1-due` or tomorrow. **Only Nick's calendar is visible** — reading a colleague's free/busy needs `Calendars.Read.Shared`, which NEURO doesn't hold, so the slot is guaranteed free for Nick and merely offered to them. Booking stamps `next-1-2-1-due` but NOT `last-1-2-1` — that only moves when a note proves the meeting happened. **"Book all outstanding"** on the SARA card runs `planAll()`, which fetches the calendar ONCE and reserves each allocation back into that working set — proposing people individually returns the same free slot to everyone, so booking a dozen would stack them all on one another. Reserving as it goes also lets `MAX_PER_DAY` count the 1-2-1s the plan is itself creating, so a batch spreads across days; most overdue first, so a diary that runs out short-changes the least neglected. `bookAll()` is sequential and fault-isolated (real invites to real people: one Graph failure must not abandon the rest, and nothing is retried) and re-checks each slot for a clash immediately before creating it. - **Stress score (14 Aug 2026)** — `services/stress-score.js` scores HRV against a **rolling 14-day personal baseline**, never in absolute terms: 45ms is good for one person and poor for another, so an absolute threshold would be noise. Stats are robust (median + MAD, not mean + stdev) and HRV is handled in **log space** because it is log-normally distributed. Below 7 days / 20 samples it returns `status:'calibrating'` and `score:null` rather than inventing a number; with no HRV reading in 6h it returns `'stale'`. Heart-rate-above-resting is a 30% term that only counts if <60min old — it exists because the watch samples HRV a handful of times a day but HR every few minutes. **Apple Health cannot distinguish exercise from stress**, so a >35% HR elevation adds a `caveats` string rather than being silently folded in. Score is clamped 2–98 — a bare 0 or 100 implies certainty the data doesn't support. Backed by `health_samples` (metric, value, recorded_at) with `UNIQUE(metric, recorded_at)` so a repeated poll folds instead of skewing the baseline. `/api/health/ingest` now ALSO **merges** into the daily KV blob instead of overwriting it — at a 30-min cadence a post carrying no HRV would otherwise null out the morning's reading. Pinned by `stress-score.test.js`; retuning the curves should fail those tests.
- **Scheduled jobs catch up after a restart (15 Aug 2026, #80)** — `node-cron` is in-process with NO catch-up, so anything due while `neuro-backend` was restarting simply never happened: the 02:30 sweep ran **9 nights in 45** and the Friday hygiene pass **4 Fridays in 7**, against 34 days of Pi uptime and 49 backend restarts. Dates are stamped in LOCAL time (the Pi may run UTC). `watchdog.checkScheduledJobs()` alerts on daily >3d / weekly >10d, so a job that stops is now loud. Tracked: `nightly-sweep`, `nightly-rollup`, `embeddings-rebuild`, `weekly-review`, `weekly-hygiene`, `knowledge-reflection`. Pinned by `scheduler-catchup.test.js`.
- **MoSCoW/lane calibration: words that say WHEN, not WHAT (15 Aug 2026, #73/#74)** — `todo-intelligence.js` splits `URGENT_NOW` (urgent, asap, today, before lunch, breach, disciplinary) from `DOMAIN_TERMS` (review, approval, customer, sla, escalat, payroll, ticket, queue). Pinned by `todo-intelligence.test.js`.
- **Reaching past the actions cap (15 Aug 2026, #108)** — `/api/actions` takes `type|kind|owner|source|month` + `offset`/`limit` and returns `filteredTotal`/`hasMore`/`facets`. Before it, "show more" only revealed what had already been SENT, so **347 of 467 pending actions were unreachable**. `month` comes from the NOTE date in `sourcePath`, not `created_at` — the backfill ran in one night across March–August, so keying on creation would put all 463 in one bucket. `POST /api/actions/bulk-reject` takes the same filter: **reject only, never approve** (approving runs executors, one of which sends email), requires a non-empty filter, **refuses outright if the matched set contains anything outbound**, and supports `dryRun` so the confirm quotes a true number. Pinned by `routes/actions-filter.test.js`.
- **Time awareness (15 Aug 2026, #87)** — `services/time-fit.js` + `GET /api/time/gap` / `/api/time/what-fits`, rendered by `TimeFitCard` above the Must Move lane. `tasks.estimate_minutes` is NULL when not estimated, snapped **up** to coarse buckets (5/15/30/60/120/240) — rounding down is how a "this fits" stops being trusted. An un-estimated task is assumed 30 min and **flagged `assumed: true`** on every row, never silently; the estimate control sits on that row, because asking for 128 estimates up front is how the priority field ended up 18% populated. Reads `calendar_cache`, not Graph — an instant answer is the feature; and `calendarKnown: false` keeps "I can't see the diary" distinct from "you're free". A 5-min buffer is left before the next meeting; all-day/cancelled/free events are not walls, tentative ones are. Ranking is the existing `rankTasks` order **cut** to what fits, never re-sorted by duration — that would quietly become the quick-wins list that already exists. Nothing learns durations from completion timestamps yet, deliberately: there is no body of finished estimated tasks to calibrate against. Pinned by `time-fit.test.js`.
