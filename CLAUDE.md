# NEURO — Nick's Executive Utility & Reasoning Orchestrator

Personal AI-powered productivity system. Aggregates Jira queue, Obsidian vault, Microsoft 365 (calendar/tasks/email), Strava, location tracking, and AI chat into a single PWA. Runs on Raspberry Pi 5 (16GB) via Tailscale, installed as PWA on iPhone.

## Tech Stack
- **Backend:** Express 4 + Node.js (CommonJS, `require()` — NOT ESM)
- **Frontend:** React 19 + CSS modules (per-component `.css` files) + Vite
- **Database:** better-sqlite3 (native SQLite, WAL). Writes commit immediately — no flush step, and external scripts can read while the server runs.
- **Auth:** PIN-based (`X-NEURO-PIN` header) + API token for machine clients (n8n)
- **AI:** Anthropic SDK (Claude) + Ollama (local models on Pi) with AI routing layer
- **External:** Jira REST, Microsoft Graph (MSAL device code), Strava OAuth, OwnTracks, Obsidian vault filesystem, n8n webhooks, web-push notifications
- **Monorepo:** npm workspaces — `backend/`, `frontend/`, `worker/`
- **Worker:** Separate Express app (port 3002) on Pi 4 for background AI tasks (email triage, import classification, journal prompts, transcript processing). Uses Ollama locally. Worker is stateless — it only processes, never decides.

## Architecture

### Backend (`backend/`)
- `server.js` — Express bootstrap, PIN auth middleware, route wiring, SPA fallback (262 lines)
- `db/database.js` — sql.js init, state KV store, query helpers
- `db/schema.sql` — Full schema (conversations, jira cache, todos, calendar, inbox, vault embeddings, entities, do-next, location visits, task MoSCoW, nudges, SARA actions, daily summary)
- `routes/*.js` — ~40 Express route modules (CommonJS `module.exports`), incl. `vault-hygiene` (lint / contextual-link / alias-suggest)
- `services/*.js` — ~45 business logic modules including AI pipelines, vault access, Jira sync, Microsoft Graph, scheduling, and `vault-hygiene` (deterministic vault-graph maintenance)

### Frontend (`frontend/src/`)
- `App.jsx` — Main SPA shell, tab navigation
- `components/*.jsx` — ~35 view components, each with matching `.css` file
- `api.js` — API client with PIN header injection
- `cacheStore.js` + `useCachedFetch.js` — IndexedDB offline caching (idb library)
- `usePushNotifications.js` — Web push subscription management
- `voiceUtils.js` — Voice input utilities

### SARA mobile (`sara/app/`)
- The PWA on Nick's phone. Seven tabs: Focus, Tasks, Capture, Voice, Chat, Prep, Brain.
- `views/Tasks.jsx` is the browsable task list — before it, capture was one-way on mobile and the only way to tick something off was to arrive via a notification. Reads `/api/todos/focus` so its ranking matches Focus and the rest of NEURO.
- `completeTask.js` is the ONE place that knows how to close a task, shared with `NotificationActionCard`. Owner order is `task_id` → `ms_id` → `filePath`+`lineNumber`; getting it wrong is silent (a null `filePath` just 400s and the task stays open).
- Tab ids must also exist in `SARA_LITE_TABS` in `shared/action-surfaces.cjs`, or notification routing falls back to Focus.

### Worker (`worker/`)
- Separate Express app on port 3002 for Pi 4
- Ollama-powered AI tasks only — email triage, import classification, journal prompts, transcript processing
- Auth via `WORKER_SECRET` header
- Stateless: processes tasks, returns results, owns no data

### MCP Server (`mcp-server/`)
- Standalone MCP server exposing NEURO APIs as tools for external Claude Code sessions
- Vault tools are **NEURO-first with local-vault fallback**: they call `/api/vault/*` (writes re-index embeddings/entities via vault-hooks); on transport failure (Pi down) they fall back to direct filesystem access via `OBSIDIAN_VAULT_PATH`, served by the `localVault` helper + `vaultDispatch` circuit breaker. NEURO reconciles offline writes on next startup (hash-based `rebuildEmbeddings`). `delete_note` is NEURO-only (needs index cleanup); `vault_backlinks`/`related_notes` degrade gracefully offline.
- Env: `NEURO_URL`, `NEURO_PIN`, `NEURO_VAULT_KEY` (→ `X-Api-Key` for `/api/vault`), `OBSIDIAN_VAULT_PATH` (local Syncthing copy for fallback)

## Key Patterns
- **CommonJS throughout backend** — `require()` / `module.exports`. NOT ESM. No `import` statements.
- **PIN auth middleware** — all `/api/*` routes require `X-NEURO-PIN` header or `?pin=` query param. Machine clients use `X-NEURO-API-TOKEN` instead.
- **State KV store** — `db.getState(key)` / `db.setState(key, value)` for runtime state (sync status, last errors, etc.)
- **AI routing (policy rewritten 14 Aug 2026)** — `ai-routing.js` routes by **latency need, not by vendor ladder**. `LATENCY_SENSITIVE_TASKS` (chat, standup/EOD interactive + questions, email draft/summary, briefing synthesis) → **OpenRouter first**, because the Pi's local models are too slow to hold a conversation with. Everything else — light, scheduled, background — → **Ollama first**, cloud only if local fails. `_providerOrder(taskType)` is the single source of that decision and both `runTask` and `runStreamingChat` iterate it. **Anthropic and OpenAI are backstops, never the default**: they were tiers 1 and 2 until the Anthropic key ran out of credit and, being first in line, took chat and the standup down with it. Pinned by `ai-routing.test.js` — if you change the order, those tests should fail. Tool calling: `getToolProvider(taskType)` picks the provider for a tools turn (OpenRouter preferred, Anthropic fallback, null if neither) — both providers expose an identical `chatWithTools(systemPrompt, messages, tools, runTool, options)` returning `{text, usage, toolCalls}`, so callers stay provider-agnostic. Ollama has no function-calling API, so no cloud provider = no tools, and chat/standup degrade to plain conversation rather than pretending.
- **Vault sync** — Syncthing over Tailscale (replaced Git-based sync). Obsidian vault at `C:\Users\NickW\Documents\Nicks knowledge base`
- **Plaud intake** — `plaud-sync.js` writes transcript + preferred Plaud summary/Obsidian note, then `imports.js` routes the note of record into canonical vault paths: meetings in `Meetings/YYYY/MM/` and transcripts in `Meetings/transcripts/YYYY/MM/`, while enriching people links and keeping backlinks aligned
- **Plaud cleanup** — `/api/plaud/cleanup` and `imports.backfillPlaudNotes()` backfill historical Plaud notes, re-route legacy meeting-note copies into correct folders, archive duplicate variants, and write a cleanup report into `Documents/System/SARA Import Reports/`
- **Vault hygiene** — `services/vault-hygiene.js` is the deterministic graph-maintenance engine (pure CommonJS, takes vault root so it runs in-process or standalone via `node`). Capabilities: `lint`, `contextualLinkPlan`/`Apply`, `aliasSuggest`, `fixPlan`/`fixApply` (tiered: skip|conservative|moderate|aggressive — links default conservative=exact-only; fuzzy mislinks here so it's review-only), `connectOrphans` (fallback), `graphConfig`. Read-only by default; mutating ops are append-only/surgical, back up every touched file to `Scripts/.lint-backups/<ts>/`, write a changelog, and are idempotent (markers `<!-- ctx-links -->`, `<!-- hub-link -->`, `<!-- daily-nav -->`). Precision rules: FULL-NAME matching only, strip wikilinks/code/paths before matching, resolve path-form links when deduping, skip names mapping to >1 person. Reports → `Documents/System/Vault Audit/`. Exclude set must include generated output (`Vault Audit`, `.lint-backups`, `Archive`…) or scans self-pollute. Wired into the scheduler as a READ-ONLY Friday 4:35pm pass (refreshes lint + link cards, never applies). Ports of the throwaway `Scripts/_*.js` prototypes; full spec in `Projects/NEURO/Vault Hygiene Engine — Build Handoff` (vault).
- **PLAUD reconcile/repull** — `plaud-sync.js` `reconcilePlaudRecordings()` (read-only) lists every PLAUD recording and finds those with no ACTIVE note (Archive excluded) by plaud_id or date+title-token Jaccard ≥0.5; `repullPlaudRecordings({ids?,limit?})` re-pulls them FRESH (never from Archive) through the existing throttled (750ms gap, concurrency 1), 429-backoff-with-jitter, ledger-persisted-per-recording pipeline — resumable: a crash continues from the ledger. The §9.3 "no throttling" lesson was about the separate Obsidian plaud-mcp-sync plugin, NOT this service.
- **Pi health** — `services/pi-health.js` reads live host state (load, SoC temp, `vcgencmd get_throttled` decoded to named flags, `/proc/meminfo` MemAvailable, `df`, SMART via `sudo -n smartctl -d sat`, `pm2 jlist`, `systemctl is-active`, `ps`). Pure read-only, no DB. Every section degrades to `null` off-Linux or when a tool is missing, so it doesn't break Windows dev. SMART cached 5min (spins the disk), PM2 15s; a 60s in-memory ring buffer (120 samples, `.unref()`) feeds the trend sparklines. `assess()` turns raw numbers into the ranked issue list the panel's focus band renders — that judgement lives in the backend, not the component.
- **Tasks: NEURO is the source of truth** (13 Aug 2026) — the `tasks` table owns text, status, MoSCoW, priority 1-3, due date and a provenance backlink. `task_moscow` is folded in and no longer written. All four capture routes write to the DB: `/api/capture/todo` (Watch/Siri + Capture tab), chat, MCP `create_task`, and SARA suggestion approval — `obsidian.addTodoToMasterList()` is now a thin wrapper that creates a task rather than appending markdown, which retired both the `📥 Inbox` heading guessing and `#mustdo`. `services/task-store.js` is the only writer (dedupe_key = normalised text, UNIQUE, so a second sighting folds rather than duplicates); `task-export.js` regenerates `Tasks/NEURO Tasks (export).md` (read-only copy + "last exported" stamp = the offline safety net and the rollback path; `verifyExport()` compares it to the DB by task id); `task-import.js` seeded 130 tasks from `Master Todo.md` with MoSCoW/priority from the 12 Aug triage worksheets. `parseVaultTodos()` merges DB rows and dedupes file-backed lines against them, so every consumer sees tasks unchanged. Microsoft Tasks and daily notes stay file-backed — Microsoft and the daily note own that data. `Master Todo.md` is still parsed as a fallback until `agent_state` key `tasks.master_todo_retired` is set (`POST /api/tasks/retire-master`, refuses unless the export verifies).
- **Route 3 — the Obsidian capture drop-box** — `Tasks/Capture.md` is a DROP-BOX, NOT A STORE. `task-capture-drain.js` creates the tasks and CLEARS the line (scheduler every 10 min + on startup, audit trail in `Tasks/Archive/Capture drain log.md`). If lines lingered it would silently become a second source of truth. Being one-way is why capture keeps working while the Pi is down. Inline hints: `!must` `p3` `@YYYY-MM-DD`. Deliberately NOT named `New ToDos.md` — an old file by that name is in `Tasks/Archive/`.
- **Two-way Microsoft writes** — Graph delegated scopes are `Calendars.ReadWrite, Mail.ReadWrite, Mail.Send, Tasks.ReadWrite, User.Read, Chat.Read, People.Read` (`GRAPH_SCOPES` in `microsoft.js`) — the three widened/added on 14 Aug 2026 (calendar create, mark-read on dismiss, name→email) are all user-consentable, so the device-code flow still completes without admin approval; MSAL persists to `.ms365-token-cache.json` so restarts keep auth. Adding a scope needs a fresh device-code flow (`POST /api/microsoft/auth`) AND tenant admin approval — the consent screen raises the request. `graphFetch` is GET-only; writes go through `graphWrite`. Email replies use `/me/messages/{id}/reply` (threads + quotes) and dismiss from triage on send. Task completion: To Do PATCHes `status`, Planner needs an `If-Match` etag so it reads first — `Tasks.ReadWrite` covers both, `Group.ReadWrite.All` is NOT required. The vault stores only a bare `<!--id:...-->` with no list, so `fetchTodoTasks` caches task→list and a cold start searches the lists. `/api/todos/complete-ms` reports whether the push landed and keeps the Power Automate webhook as fallback; the vault line toggles either way.
- **Standup/EOD as a session (14 Aug 2026)** — `services/standup-session.js` replaces the fixed three-question stepper with a tool-using conversation. State machine `active → ready → finished`, one session per day per kind, persisted in `agent_state` as `standup_session_<kind>_<date>` (KV, not a table — a schema migration on the live DB is a bigger risk than the query convenience is worth). **The transcript is saved before AND after every turn**, which is the whole point: the old flow held everything in browser state until one final POST and lost it all when that POST failed. Tools: `resolve_commitment` (a carry of 3+ days must be decided, and `scheduled` only counts if it creates a dated task), `set_focus` / `set_eod_summary` (mark the session ready), `create_task`, `complete_task`. Context is gathered deterministically up front from `standup-accountability` + working memory + task store — a standup that pauses to search the vault is a standup that gets skipped. `finish()` renders the note; it does NOT scrape a `===DAILY_NOTE_START===` marker out of the model output like `/interactive` did. **The `## Focus Today` / `## Carry-Overs` headings are a contract** — `standup-accountability.parseDailyNote()` reads them back tomorrow to work out what was carried, so changing them silently breaks accountability. Routes: `/api/standup-session/:kind/{start,reply,finish,abandon}` + GET to resume; failures return 503 `retryable:true` WITH the saved session so the client can retry without retyping. Falls back to a tool-less conversation when no tool-capable provider is available (`session.degraded`). The old `GuidedStandup`/`GuidedEod` components in `StandupEditor.jsx` are now unreferenced — left in place deliberately while a second session is active in the repo.
- **Chat tool use (14 Aug 2026)** — `services/chat-tools.js` gives chat hands; before this it was read-only RAG, so "mark that done" / "book an hour for it" were impossible by construction. Three tiers, and the tier IS the safety model: `read` (get_queue, get_tasks, get_calendar, search_vault, read_note, get_urgent_emails) has no side effects; `write` (create_task, complete_task, append_daily_note) is reversible and internal, so it runs immediately; `queued` (draft_email_reply, schedule_focus_block) NEVER executes in chat — it creates a pending `sara_action` and the send/booking happens only on approval. The agentic loop is `anthropic-provider.chatWithTools()` (max 5 rounds, history normalised first because the tool API rejects the malformed histories the text path tolerates). Only Anthropic supports tools, so other providers fall back to the text-only path rather than pretending. Gated by `ai-routing.isCloudAllowed('chat_sync')` so AI_MODE and the daily budgets apply; the loop reports its own usage via `ai-routing.recordUsage()` or tool turns under-count. Kill switch `CHAT_TOOLS_ENABLED=false`. With tools live the `[ADD TODO:]` marker is suppressed in the prompt — otherwise the task is created twice. `read_note` resolves inside the vault root and refuses anything else: a model-supplied path is untrusted input.
- **SARA actuators (14 Aug 2026)** — `suggestion-engine.executeAction` is async and does real work, not just navigation: `reply_email` (Graph send + triage dismiss), `complete_task` (task store + Graph push + vault mirror), `schedule_focus_block` (Graph calendar create). Outbound email is deliberately two-gated — `draft_reply` writes the words and queues a separate `reply_email` action carrying them, so nothing sends until Nick has read the draft and approved again. Knock-ons: `/api/actions/batch` no longer runs inside `db.batchSaves()` (better-sqlite3 transactions are sync-only, and the flush-batching it existed for died with sql.js), and `action-candidates.js` lost its hard-disabled auto-promote branch because that function is sync and would have marked every promotion failed. `suggestion-engine.queueAction()` is the front door for anything that wants SARA to act without acting itself.
- **Notification governor (14 Aug 2026)** — every `webpush.sendToAll()` passes `_governor()`: quiet hours (`PUSH_QUIET_HOURS`, default `22:00-07:00`, `off` disables), 30-min dedupe on type+title+body, hourly cap (`PUSH_HOURLY_CAP`, default 6). `ALWAYS_DELIVER` types (escalation_alert, meeting_alert, system_alert, capture_failed, test) bypass quiet hours and the cap but NOT dedupe — the same escalation arriving via both the nudge path and the alert path is still one escalation. State persists to `agent_state.push_governor`: an in-memory budget resets on every restart, and the backend restarts several times a day. 25 call sites send push and none of them knew about each other.
- **Calendar writes (14 Aug 2026)** — `POST /api/calendar/events` creates on `/me/events` via `graphWrite`; needs `Calendars.ReadWrite`. `POST /api/calendar/parse` turns free text ("2pm tomorrow with abdi for 30 mins") into a draft and creates NOTHING — `event-parser.js` is regex-first (instant, works with the Pi offline), and only spends a model call via `aiRouting.runTask('event_parse')` when the rules find no time. The composer always confirms before creating, because attendees mean Graph emails real invites. `contact-directory.js` resolves names in trust order: People note `email:` frontmatter → senders already in the triage blob → Graph `/me/people` (`People.Read`). It never guesses — >1 match comes back `ambiguous` for Nick to pick, 0 comes back `unresolved`. **All 15 team People notes now carry `email:` (14 Aug 2026)**, so every direct report resolves from `vault` without touching Graph — instant, and it still works with Graph down. This was not cosmetic: Naomi, Adele and Maria each have a *personal* address (gmail/yahoo) sitting beside their work one in Graph, so all three came back `ambiguous`, which the booking path treats as unresolved and would have booked with **nobody invited**. Local contacts are matched before Graph is consulted, so the frontmatter short-circuits it. Keep `email:` populated when adding a person.
- **Calendar timezone** — Graph answers in UTC unless asked otherwise, and the UI slices times straight out of the string, so every BST event read an hour early. `fetchCalendarEvents` now sends `Prefer: outlook.timezone="Europe/London"` (`EVENT_TIMEZONE`, env `NEURO_TIMEZONE`), which fixes the times AND makes Graph read the day window as local. Writes pass naive wall-clock + the same zone name, so no code converts offsets by hand. The ICS fallback had the same bug independently — `parseIcsDate` now converts trailing-`Z` values via `Intl` against `NEURO_TIMEZONE`, deliberately NOT the host clock, since the Pi may run in UTC. Anywhere building a date string must use local getters, never `toISOString()`.
- **The person graph (14 Aug 2026)** — `People/*.md` filenames ARE the roster; every consumer reads the folder, and nothing hardcodes a name list. `entities.js` used to carry a 20-name `TEAM_MEMBERS` array and store the **first** name (`Hope`), while `person-detail` looked mentions up by **full** name against an exact-match query — so every person page's Mentions block was empty by construction. Now: `getRoster()` (5-min cache) reads People/, matches full names always and a first name **only when it maps to exactly one person** (Nathan is both Button and Rutland), whole-word (`includes()` fired "Liam" inside "William"), and stores the full name. `getMentionsOf()` folds in legacy first-name rows so pages aren't blank until the nightly sweep re-walks. Attendee extraction in `imports.js` matched `### Attendees` only — present in 6 of 229 meeting notes, because PLAUD writes `## Mentioned` — so `people:` frontmatter was empty almost everywhere; `PEOPLE_HEADING_RE` now takes either at `##`/`###`. Unmatched names are recorded **bare**, never as `[[People/{slug}]]`: inventing that link is what produced the dangling `{Name}`/`Speaker 1` links. Backfill for existing notes is `POST /api/imports/restamp-people` (`restampMeetingPeople`, dryRun by default, backs up to `Scripts/.lint-backups/`) — it rewrites ONLY the `people:` block by hand, deliberately NOT via `updateFrontmatter`, whose line-based reserialise silently drops list values.
- **People gap pass** — `services/people-gap.js` is the only thing that ever proposed a People note (person-profile.js is reachable only from its route and the MCP tool, both manual — which is why no People note had been touched since 3 July). Sources are all pre-existing: meeting-note attendee sections, triaged inbox senders on an internal domain (`PEOPLE_GAP_DOMAINS`, default `nurtur.tech` — customers and vendors would flood the folder), and `calendar_cache` organizers (that table has no attendee column, so organizer is all there is). A name needs 2+ sightings and 2+ words. Follows the vault-hygiene convention: the nightly 10pm pass is **READ-ONLY** and reports to `Documents/System/Vault Audit/`; creating stubs is an explicit `POST /api/people-gap/apply`. Stubs carry `status: auto-stub` and no 1-2-1 cadence — NEURO doesn't know whether the person is a report.
- **1-2-1s are detected, not declared (14 Aug 2026)** — `services/one-to-one-detect.js` derives `last-1-2-1` from the meeting notes in `Meetings/`, because the hand-maintained frontmatter froze in March 2026 while 1-2-1s carried on happening: the Team board showed people 100+ days overdue who had been seen in July. Two rules carry it. (1) **A prep note is not a 1-2-1** — `type: meeting-prep` notes are NEURO-generated *before* a meeting and carry `meeting-type: "1-1"` like the real thing; Heidi had five, each generated off the same stale date with no meeting behind any of them, so counting them would close the loop on itself. `type` must be `meeting` or `transcript` (an orphaned transcript is often the only surviving evidence — the Plaud reset archived some summaries). (2) **Attribution needs the body to agree** — frontmatter `people:` links are Plaud-generated and often incomplete (the 4 Jun three-hander links only Stephen), so a candidate must also dominate the mentions (`MIN_MENTIONS` 12, `DOMINANCE` 0.6), and a title naming 2+ of the team is a group meeting outright. `syncPeopleNotes({apply})` stamps frontmatter and **only ever moves a date forward**, so a manual entry for a meeting not yet written up survives. Runs in the 10pm scheduler block; cached in `agent_state.one_to_one_index`. `GET /api/1to1/recent` feeds the board's "Last 1-2-1" card. **Vault notes are mixed CRLF/LF — normalise before any line-anchored regex** (`\r` is a JS line terminator, so `/^key:\s*(.*)$/` silently fails on every CRLF line).
- **1-2-1 booking (14 Aug 2026)** — `services/one-to-one-booking.js`, "Book now" on the Team card. Two-step like `event-parser`: `propose()` reads the calendar and returns a draft, `book()` creates it — attendees mean Graph emails a real invite, so nothing is created by looking. **Nick's booking rules are expressed as two windows rather than a pile of exclusions** — `AM_WINDOW` 10:00–12:00 and `PM_WINDOW` 14:00–16:30 (bounds in minutes so 16:30 is expressible). That makes "never at 9am", "never 12–2" (the gap between them IS lunch) and "never after 4.30pm" (a slot must *finish* inside its window, so a 30-min 1-2-1 starts no later than 16:00) true by construction. Plus "never when a meeting already exists" (clash detection; tentative blocks, only free/cancelled don't) and `MAX_PER_DAY = 2` via `countOneToOnes()`, which matches existing 1-2-1s by subject however they were named. PM is tried first — every entry in the vault's 1-2-1 Tracker reads "PM". Working days only, from `next-1-2-1-due` or tomorrow. **Only Nick's calendar is visible** — reading a colleague's free/busy needs `Calendars.Read.Shared`, which NEURO doesn't hold, so the slot is guaranteed free for Nick and merely offered to them. Booking stamps `next-1-2-1-due` but NOT `last-1-2-1` — that only moves when a note proves the meeting happened.
- **1-2-1 prep is NOVA's, not NEURO's (14 Aug 2026)** — `POST /api/1to1/prep`, `GET /api/obsidian/people/:name/121-prep/latest`, the MCP `generate_1to1_prep` tool and the board's prep buttons were all removed; NOVA's `one21-service.ts` owns prep, sessions and action tracking. `services/one-to-one-prep.js` survives unreferenced — delete it once NOVA is confirmed to cover everything.
- **Nudges** — types live in `nudges.NUDGE_TYPES`. Two kinds: *tone* nudges (standup/todo/eod/journal…) draw escalating lines from the message pools, and *fact* nudges (`escalation`, `email`) state what's actually outstanding and re-state it on every nag via `syncFactNudge()` — which raises, updates in place, or clears one banner. Escalation is driven by `jira.syncEscalations()`/`markEscalationsSeen()`, email by the inbox scan and item dismissal, so both self-clear the moment the work is done. Snooze is per-type with a caller-chosen duration (`POST /api/nudges/:type/snooze` `{minutes}`, default 30, capped 24h); the banner stores snoozed-until timestamps, not booleans. Todo targeting ranks MoSCoW `must` first, matching `buildTodayLane`.
- **Stress score (14 Aug 2026)** — `services/stress-score.js` scores HRV against a **rolling 14-day personal baseline**, never in absolute terms: 45ms is good for one person and poor for another, so an absolute threshold would be noise. Stats are robust (median + MAD, not mean + stdev) and HRV is handled in **log space** because it is log-normally distributed. Below 7 days / 20 samples it returns `status:'calibrating'` and `score:null` rather than inventing a number; with no HRV reading in 6h it returns `'stale'`. Heart-rate-above-resting is a 30% term that only counts if <60min old — it exists because the watch samples HRV a handful of times a day but HR every few minutes. **Apple Health cannot distinguish exercise from stress**, so a >35% HR elevation adds a `caveats` string rather than being silently folded in. Score is clamped 2–98 — a bare 0 or 100 implies certainty the data doesn't support. Backed by `health_samples` (metric, value, recorded_at) with `UNIQUE(metric, recorded_at)` so a repeated poll folds instead of skewing the baseline. `/api/health/ingest` now ALSO **merges** into the daily KV blob instead of overwriting it — at a 30-min cadence a post carrying no HRV would otherwise null out the morning's reading. Pinned by `stress-score.test.js`; retuning the curves should fail those tests.
